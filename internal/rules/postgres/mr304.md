# MR304 · drop-table-in-use

## What it detects

`DROP TABLE` on a table that this change set didn't create, while application code still uses it.

This rule is off by default until migrail scans application code. Until then, MR502 reports every dropped table. Turn it on with `--rule MR304` to see a compatibility warning as well.

## Why it's dangerous

During a rolling deploy, instances running the previous release still query the table. Those queries fail as soon as it's gone.

## Lock & impact

| Statement | Lock | Blocks | Work |
|---|---|---|---|
| `DROP TABLE` | `ACCESS EXCLUSIVE`, briefly | all queries, only for a moment | none |

## How to fix

1. Remove every use of the table from the application.
2. Deploy.
3. Drop the table in a later deploy.

## When it's safe to ignore

- No release that is still running uses the table.

## Examples

Bad:

```sql
DROP TABLE sessions;
```

Good: remove the application code first, then drop the table in a later release.
