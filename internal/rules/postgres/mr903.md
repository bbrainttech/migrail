# MR903 · dynamic-sql

## What it detects

`DO` blocks.

## Why it's dangerous

The body of a `DO` block is PL/pgSQL. Statements inside it, including SQL built with `EXECUTE format(…)`, only exist when the block runs, so migrail can't see which tables they lock, rewrite or change. A dangerous statement inside the block isn't reported.

## Lock & impact

Unknown. It depends on the statements inside the block.

## How to fix

Review the statements in the block by hand. Move plain DDL out of the block so migrail can check it, and keep only the logic that needs PL/pgSQL inside.

## When it's safe to ignore

- You reviewed the statements in the block.

## Examples

Reported:

```sql
DO $$ BEGIN EXECUTE 'CREATE INDEX idx_orders_status ON orders (status)'; END $$;
```

Checked:

```sql
CREATE INDEX CONCURRENTLY idx_orders_status ON orders (status);
```
