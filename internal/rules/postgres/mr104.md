# MR104 · add-foreign-key-validating

## What it detects

A foreign key added to an existing table without `NOT VALID`, either as `ADD CONSTRAINT … FOREIGN KEY` or as `ADD COLUMN … REFERENCES`.

## Why it's dangerous

When you add a foreign key, Postgres checks that every existing row points at a row in the referenced table. It holds a `SHARE ROW EXCLUSIVE` lock on both tables for the whole check. Inserts, updates and deletes on both tables wait until the check finishes, and on large tables that can take minutes.

## Lock & impact

| Statement | Lock | Blocks | Work |
|---|---|---|---|
| `ADD CONSTRAINT … FOREIGN KEY` | `SHARE ROW EXCLUSIVE` on both tables | `INSERT`, `UPDATE`, `DELETE` on both tables | scans the table to check every row |
| `ADD CONSTRAINT … FOREIGN KEY … NOT VALID` | `SHARE ROW EXCLUSIVE` on both tables, briefly | the same, only for a moment | none |
| `VALIDATE CONSTRAINT` | `SHARE UPDATE EXCLUSIVE` on the table, `ROW SHARE` on the referenced table | other schema changes | scans the table |

These locks apply to PostgreSQL 12 through 18.

## How to fix

Add the constraint as `NOT VALID`. Postgres enforces it for new rows right away but skips the check of existing rows. Then validate it in a separate migration, so the validation doesn't run in the same transaction as the lock from the first step.

```sql
ALTER TABLE orders ADD CONSTRAINT orders_user_id_fkey
  FOREIGN KEY (user_id) REFERENCES users (id) NOT VALID;
```

```sql
ALTER TABLE orders VALIDATE CONSTRAINT orders_user_id_fkey;
```

For `ADD COLUMN … REFERENCES`, add the column without the reference first, then add the constraint as `NOT VALID` and validate it.

## When it's safe to ignore

- Both tables are empty or very small in every environment.
- The migration runs during a maintenance window with writes stopped.

## Examples

Bad:

```sql
ALTER TABLE orders ADD CONSTRAINT orders_user_id_fkey FOREIGN KEY (user_id) REFERENCES users (id);
```

Good:

```sql
ALTER TABLE orders ADD CONSTRAINT orders_user_id_fkey FOREIGN KEY (user_id) REFERENCES users (id) NOT VALID;
```
