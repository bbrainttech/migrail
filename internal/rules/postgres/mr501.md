# MR501 · truncate-table

## What it detects

`TRUNCATE` on tables that this change set didn't create.

## Why it's dangerous

`TRUNCATE` deletes every row, in every environment the migration runs in, including production. It also takes an `ACCESS EXCLUSIVE` lock on each table.

## Lock & impact

| Statement | Lock | Blocks | Work |
|---|---|---|---|
| `TRUNCATE` | `ACCESS EXCLUSIVE` | all queries | removes all data |

## How to fix

Confirm that deleting the data is intended. If it is, ignore the finding with a reason so reviewers see why:

```sql
-- migrail:ignore MR501 reason="orders_staging is rebuilt nightly"
TRUNCATE orders_staging;
```

## When it's safe to ignore

- The table holds data that can be rebuilt, such as a cache or a staging table.

## Examples

Bad:

```sql
TRUNCATE orders;
```
