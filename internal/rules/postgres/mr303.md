# MR303 · rename-table

## What it detects

`ALTER TABLE … RENAME TO` on a table that this change set didn't create.

## Why it's dangerous

During a rolling deploy, instances running the previous release still query the old table name. Those queries fail as soon as the rename commits.

## Lock & impact

| Statement | Lock | Blocks | Work |
|---|---|---|---|
| `RENAME TO` | `ACCESS EXCLUSIVE`, briefly | all queries, only for a moment | none |

## How to fix

Keep the old name working while the application moves to the new one:

1. Rename the table and create a view with the old name in the same transaction. A simple view over one table accepts inserts, updates and deletes.
2. Change the application to use the new name and deploy.
3. Drop the view in a later deploy.

```sql
ALTER TABLE users RENAME TO accounts;
CREATE VIEW users AS SELECT * FROM accounts;
```

## When it's safe to ignore

- No release that is still running uses the table.

## Examples

Bad:

```sql
ALTER TABLE users RENAME TO accounts;
```

Good:

```sql
ALTER TABLE users RENAME TO accounts;
CREATE VIEW users AS SELECT * FROM accounts;
```
