# MR107 · set-not-null-scan

## What it detects

`ALTER COLUMN … SET NOT NULL` on a table that this change set didn't create, unless an earlier statement in the change set added and validated a `CHECK (column IS NOT NULL)` constraint.

## Why it's dangerous

To set `NOT NULL`, Postgres reads every row to confirm the column has no NULL values. It holds an `ACCESS EXCLUSIVE` lock for the whole scan, so every query on the table waits, including `SELECT`.

## Lock & impact

| Statement | Lock | Blocks | Work |
|---|---|---|---|
| `SET NOT NULL` | `ACCESS EXCLUSIVE` | all queries | full table scan |
| `SET NOT NULL` with a validated `CHECK (column IS NOT NULL)` | `ACCESS EXCLUSIVE`, briefly | all queries, only for a moment | none |

Postgres skips the scan when a validated check constraint already proves the column has no NULL values. This applies to PostgreSQL 12 through 18.

## How to fix

1. Add a check constraint as `NOT VALID`. This takes a brief lock and doesn't scan.
2. Validate the constraint in a separate migration. Validation scans the table but only takes a `SHARE UPDATE EXCLUSIVE` lock, so reads and writes continue.
3. Set `NOT NULL`, which now skips the scan, and drop the check constraint.

```sql
ALTER TABLE orders ADD CONSTRAINT orders_status_not_null CHECK (status IS NOT NULL) NOT VALID;
```

```sql
ALTER TABLE orders VALIDATE CONSTRAINT orders_status_not_null;
```

```sql
ALTER TABLE orders ALTER COLUMN status SET NOT NULL;
ALTER TABLE orders DROP CONSTRAINT orders_status_not_null;
```

## When it's safe to ignore

- The table is empty or very small in every environment.
- The migration runs during a maintenance window with traffic stopped.
- A validated `CHECK (column IS NOT NULL)` constraint already exists from an earlier, already-applied migration. migrail only sees constraints added in the current change set.

## Examples

Bad:

```sql
ALTER TABLE orders ALTER COLUMN status SET NOT NULL;
```

Good:

```sql
ALTER TABLE orders ADD CONSTRAINT orders_status_not_null CHECK (status IS NOT NULL) NOT VALID;
ALTER TABLE orders VALIDATE CONSTRAINT orders_status_not_null;
ALTER TABLE orders ALTER COLUMN status SET NOT NULL;
ALTER TABLE orders DROP CONSTRAINT orders_status_not_null;
```
