# MR905 · unused-ignore

## What it detects

A `migrail:ignore` or `migrail:ignore-file` comment that doesn't suppress any finding: the rule it names isn't reported for the next statement or the file.

## Why it's dangerous

Stale ignores pile up and hide future findings by accident. If the statement later changes in a way that triggers the rule, the old comment silences it without anyone deciding that it's safe.

## Lock & impact

None.

## How to fix

Remove the comment, or move it directly above the statement it's meant for and check the rule ID.

## When it's safe to ignore

Never needed. Delete the comment instead.

## Examples

Reported, because `CREATE INDEX CONCURRENTLY` doesn't trigger MR101:

```sql
-- migrail:ignore MR101 reason="small table"
CREATE INDEX CONCURRENTLY idx_orders_status ON orders (status);
```
