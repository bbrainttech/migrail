# MR901 · parse-error

## What it detects

A statement that the database's own parser rejects.

## Why it's dangerous

The database rejects this statement too, so the migration fails when it runs. migrail can't check a statement it can't parse, so no other rule covers it. migrail still analyzes the other statements in the file.

## Lock & impact

None. The statement fails before it takes any locks. If the migration runs in a transaction, Postgres rolls back the statements before it.

## How to fix

Correct the syntax at the reported position. The message comes from the Postgres parser, for example `syntax error at or near "COLUM"`.

If the file uses syntax for another tool, such as `psql` meta-commands like `\connect`, remove it or move it to a script that the tool runs.

## When it's safe to ignore

Never. A statement that can't be parsed also fails when the migration runs.

## Examples

Bad:

```sql
ALTER TABLE orders ADD COLUM status text;
```

Good:

```sql
ALTER TABLE orders ADD COLUMN status text;
```
