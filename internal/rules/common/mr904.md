# MR904 · ignore-without-reason

## What it detects

A `migrail:ignore` or `migrail:ignore-file` comment without `reason="…"`, when reasons are required. Reasons are required by default.

## Why it's dangerous

An ignore without a reason tells the next reviewer nothing about why the finding is safe. migrail doesn't apply the ignore, so the original finding is still reported.

## Lock & impact

None.

## How to fix

Add a reason that explains why the finding is safe here:

```sql
-- migrail:ignore MR101 reason="orders has fewer than 100 rows in every environment"
CREATE INDEX idx_orders_status ON orders (status);
```

## When it's safe to ignore

Set `policy.require_ignore_reason: false` in `.migrail.yaml` if your team doesn't want reasons.

## Examples

Bad:

```sql
-- migrail:ignore MR101
CREATE INDEX idx_orders_status ON orders (status);
```

Good:

```sql
-- migrail:ignore MR101 reason="orders is empty until launch"
CREATE INDEX idx_orders_status ON orders (status);
```
